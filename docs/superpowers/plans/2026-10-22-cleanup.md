# Cleanup and Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Bring quadlink to a clean base for the dashboard and pin/bench work: remove dead code, fix the review's bugs, give channels and slots one identity and numbering, move quad state out of QuadBuilder, keep a full channel status pool, split the daemon loop, and cover it with tests and benchmarks.

**Architecture:** Python asyncio daemon (`src/quadlink/`). One event loop owns all state; streamlink lookups run in executor threads and return plain objects. The relay (`relay/`) serves `/streams/1-4` to QuadStream clients. Source of findings: the whole-repo review summarized in `.superpowers/sdd/whole-review.md`.

**Tech Stack:** Python 3.13, aiohttp, httpx, streamlink (ttvlol plugin), pydantic, structlog, pytest, nix.

## Global Constraints

- Before every commit: `pytest` all pass; `black src/ tests/ bench/`; `ruff check src/ tests/` no findings; `mypy src/` no errors; `nix build .#default` succeeds.
- Comments lowercase, terse, why not what; no history, provenance or roadmap; acronyms uppercase; product names capitalized (Twitch, QuadStream); docstrings sentence case. User-facing error text: plain active-voice English.
- Commit format: `<terse description>`, optional details, then the two attribution lines the controller gives.
- QuadStream (AVPlayer) plays every served second at real speed and never skips; a playlist unchanged > 1.5 × target duration (3 s) rebuilds players; a slow segment request stalls the tile.
- Relay URLs stay `/streams/1`–`/streams/4` (every client's tile config uses them). Inside quadlink, slots are numbered 0–3 (matching QuadStream's `stream0`–`stream3` prefs); convert only at the HTTP boundary.
- Channel identity is the lowercase Twitch login everywhere.
- No behaviour change to the relay's audio conversion, splicing, filler or timing unless a task says so.
- duke runs quadlink as a NixOS service (nix/module.nix); Docker is not a deploy path.

### Task 1: dead code and broken packaging

Delete: `docker/` and any Docker references (README, flake, workflows); the hosted-channel logic (`skip_hosted`, `hosted_offset`, `_is_hosted` and config/docs for them — Twitch removed hosting, and the check drops channels whose display name differs from their login); config fields that do nothing (`StreamGroup.limit`, `Config.logging`, `Webhook.timeout`) and their README/`config.yaml.example` entries; `QuadBuilder.previous_quad`, `types.QuadPosition`, `ConfigLoader.has_config`, `HealthServer.mark_not_ready`, the no-op `except CancelledError: raise` in daemon.py, the dead `if not config` branch. Fix the 6 test RuntimeWarnings (tests/test_main.py patches the async `run_daemon` with an AsyncMock that is never awaited). Fix package.nix `version` to match pyproject. Old configs that still contain removed keys must still load (ignore them, with one deprecation warning at load).

### Task 2: small bugs

One-shot mode exits after "no candidates", an empty quad or a login failure; credential changes are picked up on reload (rebuild the QuadStream client when credentials change); the processor's ThreadPoolExecutor is shut down on reload; `channel_url("twitch.tv/foo")` produces `https://twitch.tv/foo`; duplicate authors keep the first (highest-priority) candidate; log levels: "quad channels dropped from live pool" → info, failed login logs status only (not the body), "relay source fetch failed" logged once per failure streak per slot; `/ready` reflects a loop heartbeat (not ready if no cycle completed within 3 intervals); with `--webui` and no config file, start the web UI and wait for a config rather than exiting.

### Task 3: canonical channel key and 0–3 slots

Add `channel: str` (lowercase login, from the plugin's login or the URL) to `Stream`/metadata in the fetcher; dedupe and key by it in the processor, QuadBuilder, daemon (`_on_screen`, `_dropped_from_pool`), SlotStore and relay identities. Renumber internal slots 0–3 (SlotStore, SlotRelay, SegmentProxy, logs, `Quad` model fields `slot0..3` or a list), converting at the `/streams/{1-4}` routes. Update tests.

### Task 4: QuadState and a pure compose

Split QuadBuilder into a pure `compose(pool, state: QuadState, overrides, config) -> QuadState` (overrides is an empty placeholder type for now) and a `QuadState` the daemon owns (slot → channel positions, categories, last successfully pushed quad). A config change replaces only the config, never the state (fixes tile reshuffle on save). The daemon pushes to QuadStream while the composed quad differs from the last successful push (fixes no-retry). Preserve all current selection behaviour (stability, saturation, diversity, continuity bonuses; sticky positions; newcomers take freed slots lowest-first); existing quad tests must pass unchanged in intent.

### Task 5: channel status pool

The processor returns every configured channel with a status: live (with title, category, login, playlist URL), offline, no video (audio-only), rejected (filter reason), lookup failed. The daemon keeps the latest pool and the time it was refreshed. Selection uses the live subset. Thumbnail URL for live channels: `https://static-cdn.jtvnw.net/previews-ttv/live_user_{login}-320x180.jpg`.

### Task 6: split the loop

Two loops on the event loop: refresh (slow, every `interval`, runs lookups and updates the pool, then requests a recompose) and recompose (fast: compose from the cached pool and state, update SlotStore, push when needed). A recompose request is an `asyncio.Event`; anything (refresh, a future web action) can set it. Recompose is the only writer of SlotStore and the push. Lookups across priority levels run concurrently (bounded) instead of one level after another, if Task 8's measurement shows it shortens the cycle.

### Task 7: tests

Daemon-loop tests with real Config objects (not MagicMock) covering: config reload keeps positions, push retry after a failure, one-shot exits, refresh/recompose interplay. Web UI tests stay green. Every test asserts something.

### Task 8: benchmarks

Measure cycle time vs number of configured channels and lookup concurrency (synthetic fetcher with realistic latency distribution), before and after Task 6; re-run `bench/relay_memory.py` (4 slots incl. fMP4) to confirm no relay regression. Record results in the bench README section.

### Task 9: final review

Fresh whole-repo review; fix findings; deploy.
